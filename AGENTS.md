# Bark

Minimal NIP-07 browser extension that bridges `window.nostr` to a remote
NIP-46 signer: no keys in the browser. Works with any NIP-46 bunker; persona
(derive/list/switch) features require a Heartwood signer.

## Build and test

| Command | Purpose |
|---------|---------|
| `npm install` | Install dependencies |
| `npm run build` | Build for Chromium into `dist/` |
| `npm run build:firefox` / `build:safari` / `build:all` | Build the other targets |
| `npm test` | Run vitest unit tests |
| `npm run e2e:chromium` | Playwright e2e (builds first; includes the deterministic local NIP-46 signer) |
| `npm run e2e:deterministic` | Just the CI-friendly local signer path |
| `npm run e2e:approval` | Just the deny/allow-once/trust-site/protected-kind approval checks |
| `npm run package:all` | Build and zip all three browser targets |
| `npm run verify` | Test + build:all + npm audit |

## Structure

```
src/       extension source (provider, content script, background, popup, approve, policy)
docs/      setup guide, mobile comparison, store submission, release process
e2e/       Playwright specs and fixtures
test/      vitest unit tests
scripts/   store submission tooling (AMO, Chrome Web Store)
site/      bark.forgesworn.dev static site
```

### Architecture (`src/`)

| File | Role |
|------|------|
| `provider.js` | MAIN-world content script (Chromium/Firefox; Safari falls back to script-tag injection). Implements `window.nostr`. Posts messages to the content script. |
| `content-script.js` | Bridge. Relays postMessage <-> chrome.runtime.sendMessage. Validates origin and structure. Retries through MV3 worker wake-up. |
| `background.js` | Service worker. NIP-46 connection via nostr-tools `BunkerSigner`, nostrconnect pairing, approval queue, policy checks, keep-alive pings, error sanitisation, connection state. |
| `policy.js` | Pure policy engine: allow/ask/deny per method, kind, and site. |
| `popup.js` / `popup.html` | Popup UI. Instance management, QR pairing, policy settings, relay display, reconnection. Dark theme, 320px wide. |
| `approve.js` / `approve.html` | Approval surface for ask-policy requests (allow once / trust site / deny). Popup window on desktop; a foreground tab on Firefox for Android, which has no `windows` API: see `approvalSurfaceKind` in `background.js` and `docs/mobile.md`. |
| `diagnostic.html` | Extension-internal page used by e2e for storage seeding and runtime messaging. |
| `i18n.js` | Locale loader for the 53 `_locales/*/messages.json` UI translations. |

Per-target manifests are generated by `esbuild.config.js` from `src/manifest.json`.

### Message flow

```
Web page -> provider.js (postMessage) -> content-script.js (chrome.runtime.sendMessage)
-> background.js (BunkerSigner -> NIP-46 relay -> Heartwood) -> response back
```

Message types (chrome.runtime) include `bark-request` / `bark-response`
(NIP-07/NIP-44/Heartwood RPC calls), `bark-reset` (tear down connection),
`bark-status` (connection state, relay health, Heartwood mode, auth_url),
`bark-pair` / `bark-switch` / `bark-remove` (instance management),
`bark-nostrconnect-start` / `-status` / `-cancel` (QR pairing flow),
`bark-approval-query` / `bark-approval-response` (approval window RPC),
`bark-heartwood-import-confirm` (confirm or discard a staged identity import),
and `bark-prime-signer` (signer health check, signs a kind 22242 probe).

## Conventions

- British English: colour, initialise, behaviour.
- No local key material: the extension never touches private keys.
- Pure functions for testable logic: `parseMethod`, validators,
  `sanitiseError`, `buildHeartwoodArgs` are all exported and unit tested.
- Commit messages: `type: description` (`feat:`, `fix:`, `test:`, `docs:`).

## Key dependency

`nostr-tools` provides `BunkerSigner`, `parseBunkerInput`, `SimplePool`, and
crypto utilities. Pinned at `^2.23.0` (see `package.json`).

## Common pitfalls

- Safari has no reliable MAIN-world content script support; `esbuild.config.js`
  strips MAIN-world content scripts from the Safari manifest and falls back to
  script-tag injection.
- Firefox for Android has no `windows` API, so the approval surface there is a
  foreground tab, not a popup window: check `approvalSurfaceKind` before
  assuming popup behaviour.
- A request after service worker idle must reconnect instead of hanging (see
  `docs/e2e-hardening.md`).
